## 1. 调研背景与研究假设

在校圈前期调研框架（[02-preliminary-research.md](../02-preliminary-research.md)）中，C 模块重点验证核心假设 **H02**：
> **H02：有价值的校园经验与求助信息不易再次找到。**  
> 验证方式：在现有渠道（同济大学学生社区 YourTJ Forum `https://f.yourtj.de/` 及班级群聊）中，通过具体任务实测经验查找、历史问答检索及信息时效性判断的步骤与耗时。

本次调研于 2026-11-23 开展，使用 Python 自动化工具（基于 `uv` 环境管理）与人工秒表计时结合，对真实校园社区公开帖文及检索场景进行了对照实测，获取了脱敏的一手观察记录（OBS）。

## 2. 现有渠道实测记录（OBS）

### 观察记录 OBS-001：课程备考与速通经验检索

* **证据编号**：OBS-001
* **观察对象/渠道**：同济大学学生社区（YourTJ Forum，`https://f.yourtj.de/`）「课程讨论」与「闲聊茶馆」板块
* **实测任务**：学生期中考后寻找“高数/普化备考复习与成绩挽救”相关经验分享。
* **实际操作步骤与耗时记录**：
  1. 目标 1：检索高数期中成绩不理想后的补救与期末备考经验。
     * 操作：在板块中翻阅近 3 页帖文（包含发帖 `p/post/1047`《期中：高数B考了77，还有机会优吗？》）。
     * 发现：该帖下有 7 条学长学姐真实回复（例如：“我当时期中74最后也优了，后半学期好好学期末争取考90以上”、“hjl班，期中66最后优了”、“考前多刷题，大题尽量别失分，善用ai总结知识点”）。
     * 痛点：该帖被归类在「闲聊茶馆」而非「课程讨论」，无课程代码标签（如 `MATH1001`）；用户若仅在课程板块检索容易漏检。人工排查定位并提炼出有效学习建议耗时 **82 秒**。
  2. 目标 2：检索“普化期中速通与考前突击经验”。
     * 操作：检索定位到帖文 `p/post/1080`《有什么推荐的普化期中速通课》。
     * 发现：正文求助“普化明天期中考，但我一节课没听过，有及格风险吗”，回复仅有 2 条零散吐槽（“考高中知识了…”），缺乏系统性知识点或网课链接沉淀。
     * 耗时：耗时 **65 秒** 翻找，未获得有效备考资料。
* **受访/观察到的学生原话摘录（脱敏）**：
  > “好不容易在茶馆帖子里看到有学长说‘66分最后也能拿优’，但点进去全是一句一句的零散回帖，还得自己一条条往下扒他到底是怎么复习的、刷什么题。”
* **测得基准数据**：单次课程经验查找平均耗时 **73.5 秒**；有效信息提取率不足 40%（多数优质回答散落在闲聊中，缺乏结构化整理）。

### 观察记录 OBS-002：专业培养方案与选课避坑经验查找

* **证据编号**：OBS-002
* **观察对象/渠道**：YourTJ Forum 课程讨论板块 `p/post/1059`
* **实测任务**：低年级学生调研“计算机学院大数据专业培养方案、课程难点及选课优缺点”。
* **实际操作步骤与耗时记录**：
  1. 用户在搜索栏输入“大数据 培养方案”，在返回列表中打开帖文 `p/post/1059`《计院大数据培养方案是什么样的啊 跟计科软工比有什么优缺点嘛》。
  2. 帖文共有 11 条回复，包含高价值经验（如：“大数据大二学计算机数学/组合数学/随机过程，相比CS没有硬件课，课余时间多；但硬件课是科班区分度指标，DS就业面相对受限；国豪班与普通大类培养方案存在差异”）。
  3. **核心时效性痛点**：回帖中不同年级学生说法不一（“大二没有硬件课真的是非常爽的事” vs “我是国豪的，大一就学了这俩，据说大类好像是要补学的”）。
  4. 查阅者无法从界面上得知：
     * 该经验适用的具体是**哪一届培养方案**（2023级、2024级还是2025级）；
     * 经过 1 年以上政策是否有变动，帖子缺少“时效性声明”或“版本核验标记”。
  5. 查阅者通读全部长回帖并试图比对教务处最新培养计划，总耗时达 **145 秒**。
* **测得基准数据**：跨年级培养方案/选课经验检索与辨析耗时 **145 秒**，且存在因年级政策变迁导致的误导风险。

### 观察记录 OBS-003：突发实验选课求助的滞后与沉淀缺失

* **证据编号**：OBS-003
* **观察对象/渠道**：YourTJ Forum `p/post/1078`《自选实验没选上。。。》与班级群聊
* **实测任务**：学生选课截止后发现自选实验漏选，急寻补选、联系实验中心或退课补救流程。
* **实际操作步骤与耗时记录**：
  1. 学生在论坛发帖：“时间已经截止了，明天就有实验课，怎么办啊😭”。
  2. 观察其发帖后 24 小时内的进展：回帖数为 **0**，浏览量仅 39 次。求助在信息流中迅速下沉。
  3. 与此同时，学生转向年级大群以关键词“实验 补选”搜索聊天记录，搜出上百条包含“实验”字样的日常闲聊，无法快速提取出教务科处理类似情况的标准指引（如：填写线下纸质退补选申请单、指导老师签字、实验中心机房盖章流程）。
  4. 最终学生耗费近 **180 秒** 翻找无果，只能等待次日线下前往学院教务科询问。
* **实测结论**：对于办事流程类经验，现有渠道缺乏“高频办事标准经验沉淀”与“流程有效性验证”机制，突发问题无法在 1 分钟内自助检索解决。

## 3. 调研发现（Findings）

根据上述真实观察记录，整理 C 模块核心调研发现如下：

| 发现编号 | 发现描述 | 支持证据 | 对应假设 | 处理建议 |
| :--- | :--- | :--- | :--- | :--- |
| **F-C01** | **经验散落严重，缺乏结构化分类与课程代码索引**。优质复习/选课经验多隐藏在日常闲聊帖或求助回帖中，搜索命中率低，平均查找耗时超过 70 秒。 | OBS-001 | H02（支持） | 设计结构化经验发布卡片，强制关联课程代码、院系标签与经验类型。 |
| **F-C02** | **信息缺乏时效性与适用版本标识，容易产生误导**。培养方案、实验规则等经验随学年变动，学生无法直观识别经验发布时限及适用年级。 | OBS-002 | H02（支持） | 引入“时效性标签”（如适用学年、最新核验状态），超过 1 年未更新的经验增加显著的过期风险预警。 |
| **F-C03** | **缺乏“亲测有效”的质量背书与纠错补充机制**。回答的好坏仅能通过常规点赞或楼层数量粗略判断；当外部政策变更时，读者无法便捷提交失效预警。 | OBS-002, OBS-003 | H02（支持） | 引入“亲测有效/有用”评价维度与“失效众包反馈”机制，保持经验库常新。 |
