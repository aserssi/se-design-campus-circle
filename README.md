# 校圈 Campus Circle

**连接同校同学，让交流更方便，让互助有回应。**

## 校圈是什么

校圈是一个面向本校学生、以**校园社交与互助**为核心的软件工程课程设计项目。我们计划围绕学生的学习和生活，建设一个能够交流话题、寻找同伴、分享经验和发布求助的校园社区。

项目以“同校”作为交流范围，以“共同话题”和“具体需求”连接学生。用户既可以围绕学习、兴趣和校园生活展开交流，也可以在遇到问题时提出求助、参与回答，并跟进问题的解决情况。有价值的回答和经验能够被整理、查找，供其他同学参考。

**项目目标：让学生更容易找到同校交流对象和有用信息，并让一次求助从发布、回应走向解决。**

项目已汇总学生访谈、公开资料与现有渠道实测，并建立 20 条待实现的需求故事。第 3 课前的调研证据、验收标准和待确认事项见下方索引。

## 面向谁，服务哪些场景

校圈的主要用户是在校学生，包括希望拓展交流圈的同学、需要帮助的同学，以及愿意回答问题和分享经验的同学。社区版主与平台管理员负责维护交流秩序和处理不当内容。

| 使用场景 | 校圈计划提供的支持 |
| --- | --- |
| 希望找到一起复习、运动或交流兴趣的同学 | 发布相关话题，发现并联系有共同目标的同校同学 |
| 遇到选课准备、学习方法或校园生活方面的问题 | 发布求助、补充问题细节、获得回答并反馈结果 |
| 希望分享课程学习或校园办事经验 | 按话题组织内容，让经验可以被检索和重复利用 |
| 遗失或拾到物品，希望找到相关同学 | 发布失物招领信息、更新进展并标记处理结果 |
| 遇到骚扰、虚假或不当内容 | 提交举报，由管理人员处理并反馈结果 |

## 为什么选择这个题目

### 1. 贴近校园生活，研究对象具体

找学习伙伴、咨询校园事务、交流兴趣和寻求帮助，都是可以具体描述、观察和讨论的场景。选择本校学生作为主要用户，便于团队接触真实使用者，了解他们当前怎样完成这些事情，以及哪些环节值得改善。

相比从宽泛的“智慧校园”概念出发，校园社交与互助有更清楚的用户和任务，便于将选题落实为可调研、可设计、可测试的项目。

### 2. 希望将即时交流与长期有用的信息联系起来

一次交流的价值不一定只属于当时参与的人：一条学习建议、一份办事经验或一个问题的解答，也可能帮助后来的同学。校圈希望把话题交流与信息分类、查找和结果反馈结合起来，让内容既能支持当下沟通，也能积累为可重复利用的校园经验。

这一方向为项目提供了明确的设计重点：怎样让用户发现相关内容、理解问题进展，并找到真正有帮助的回应。

### 3. 社交与互助能够形成连贯的业务过程

共同的课程、兴趣和生活经历可以成为交流的起点；具体的求助则为同学之间的互动提供明确目的。我们希望以“发现话题或问题—参与交流—获得回应—反馈结果”为主线，将社交与互助组织在同一社区中。

这使项目能够关注完整的使用体验，例如问题无人回应时如何处理、信息过期后怎样更新、问题解决后怎样保留有用经验，而不仅是内容的发布与浏览。

### 4. 适合开展完整的软件工程实践

校圈涉及学生、版主与管理员之间的协作，能够围绕内容发布、评论回应、信息查找、状态变化和举报处理开展需求分析与建模。身份与权限、个人信息保护、内容管理及异常处理，也为设计和测试提供了具体课题。

团队可以从真实场景出发，逐步形成需求、模型、设计、实现和测试之间的对应关系，练习课程要求的协作与工程过程。

### 5. 核心范围清楚，便于逐步实现和评价

项目初期聚焦校园交流、经验分享与日常互助，先围绕一条完整的使用流程推进，再逐步完善查找、反馈和管理能力。这有助于合理安排团队分工，控制开发工作量。

后续可邀请同学完成“找到相关话题”“发布并跟进一次求助”“查找一条历史经验”等任务，观察完成情况、操作步骤与用户反馈，用具体任务评价设计效果。

## 初步功能规划

| 模块 | 主要内容 |
| --- | --- |
| 校园交流 | 话题发布、评论互动、兴趣与学习交流 |
| 校园互助 | 学习和生活求助、失物招领、进展更新与解决反馈 |
| 经验与信息查找 | 话题分类、关键词搜索、有用经验的整理与查阅 |
| 社区管理 | 用户权限、举报处理、内容管理与个人信息保护 |

各模块的课前需求与验收标准已录入故事 Issue。管理和维护约束仍待确认，后续实现进度以 Issue 为准。
